# Backend

An app can have a backend: a module that exports `fetch`, or any Node.js / Bun server that calls `listen()` (Express, Hono, Fastify, ...). Pages reach it with a plain `fetch('/api/…')`.

> App backends currently work only on macOS and Linux; Windows support is in progress.

## Write a backend

The `server.ts` generated by `acde new my-app --backend`:

```ts
export default {
  fetch(request: Request): Response {
    const url = new URL(request.url)
    if (url.pathname === '/api/hello') return Response.json({ hello: 'world', at: new Date().toISOString() })
    return new Response('not found', { status: 404 })
  },
}
```

In the page:

```js
const answer = await (await fetch('/api/hello')).json()
```

`export default { fetch }` works on both Bun and Node.js. On Node.js, acde's preload runs it with `node:http`; requests and responses are WHATWG `Request` / `Response` objects with streaming bodies. (There's no WebSocket upgrade on Node.js.)

You can also listen yourself:

```ts
import { createServer } from 'node:http'

createServer((req, res) => res.end('hi')).listen(3000)
```

## Discovery

Without a `backend` field, acde uses the first of these that exists:

`server.ts` `server.js` `src/server.ts` `src/server.js` `server/index.ts` `server/index.js` `backend/index.ts` `backend/index.js`

To set it explicitly, or turn it off:

```jsonc
{ "backend": { "entry": "api/main.ts", "port": 8080 } }
{ "backend": false }
```

`port` defaults to 3000; it's the port the backend thinks it's listening on.

## No TCP ports

An app's backend doesn't open TCP ports on the host. At build time, acde puts a preload (`acde-listen.js`) next to the backend that replaces `listen(P)` in `Bun.serve`, `Bun.listen`, and `net` / `http` / `https` / `tls` / `http2` with a unix socket at `<app's socket directory>/P.sock`. If no port is given, it uses `PORT` / `BUN_PORT` / `NODE_PORT`, and otherwise 3000.

As a result:

- Two apps can both `listen(3000)` without conflict.
- Requests from the page to same-origin paths (`/api/x`) or to `http://localhost:<port>/…` (and `127.0.0.1`, `[::1]`, `0.0.0.0`) all go to the app's own backend.
- UDP `bind` to a specific port is rejected (`EACCES`); ports opened by native extensions on their own aren't covered.

## Bundling

`acde build` bundles the backend into a single ES module, `backend/server.js` (target node): npm packages are bundled in, while Node built-in modules and `bun` / `bun:*` stay as imports. The same output runs on both Bun and Node.js.

## Running

- The backend starts **when the app's first window opens** and stops **when its last window closes** (SIGTERM, then SIGKILL after 3 seconds). After the 4th crash within a minute, it's no longer restarted automatically.
- It runs on Bun if `bun` is on PATH, otherwise on Node.js (≥ 22.3). `acde dev` picks based on the project's JavaScript runtime.
- The environment is built from scratch: `ACDE_APP_ID`, `ACDE_APP_DATA`, `ACDE_APP_SOCKETS`, `PORT`, `NODE_ENV=production`, plus the session's `HOME`, `PATH`, `LANG`, and so on. Nothing is inherited from your terminal.
- No proxy is used: proxy variables such as `HTTPS_PROXY` are not passed to the backend, and pages don't go through the system proxy either (see [Web compatibility](../reference/web.md#network)). On a network that reaches the internet only through a proxy, requests to other hosts fail.
- The working directory is `$XDG_DATA_HOME/acde/apps/<id>/`; the app can keep its own data here.
- Backend output goes to the runtime's log, prefixed with `[<id>#backend]`. `acde dev` prints it in your terminal.

## Running it directly

To debug the built backend on its own, without the runtime, give it a socket directory and load the preload that `acde build` put next to it:

```sh
acde build
cd .acde/backend
ACDE_APP_SOCKETS=/tmp/my-app-sockets bun --preload ./acde-listen.js server.js
curl --unix-socket /tmp/my-app-sockets/3000.sock http://localhost/api/hello
```
